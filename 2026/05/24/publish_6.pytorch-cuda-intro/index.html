PyTorch CUDA 入门：异步执行与性能优化

引言：GPU 与 CUDA 概览

深度学习的成功离不开 GPU 的并行计算能力。理解 CUDA 编程模型，特别是异步执行机制，对编写高效、易调试的 PyTorch 代码至关重要。

CPU vs GPU：核心设计差异

特性 CPU GPU
核心数 少数几个强大核心（32~64） 成千上万个简单核心
设计目标 复杂逻辑、顺序执行 大量简单并行计算
擅长 分支判断、递归 矩阵运算、向量操作

GPU 的并行模式：

  • CPU 像一位数学家，一个接一个计算
  • GPU 像数千名小学生组成方阵，每人负责一个数字，同时动手，瞬间完成

CUDA 编程模型

主机与设备

GPU 是独立硬件，有自己的显存。编程时：

  • Host（主机）：CPU 端，负责发起计算、内存拷贝
  • Device（设备）：GPU 端，执行核函数（Kernel）

关键概念

  1. 内存拷贝：数据必须从 CPU 内存复制到 GPU 显存
  2. 核函数（Kernel）：在 GPU 上并行执行的函数
  3. 核函数启动：CPU 调用并启动 GPU 执行

核心：异步执行

CUDA 操作是异步的

当 CPU 调用 GPU 核函数时，不会等待 GPU 执行完成才返回，而是立即返回。

aten/src/ATen/native/cuda/jit_utils.cpp:1699-1722

核心点：cudaLaunchKernel 把核函数加入队列后就返回了，CPU 继续执行后续代码，GPU 在后台异步执行。

官方文档说明

docs/source/notes/cuda.rst:280-295

异步带来的后果

因为核函数是异步执行的，错误会延迟报告：

c10/cuda/CUDAMiscFunctions.cpp:31-44

这就是为什么 CUDA 错误经常在”不相关”的地方报出来。

调试：CUDA_LAUNCH_BLOCKING

c10/cuda/CUDAFunctions.cpp:147-154

虽然严重拖慢性能，但能准确定位问题。

Streams（流）

作用

同一个 Stream 内的操作按顺序执行。用于：

  • 确保计算顺序（如卷积 → 激活）
  • 掩盖内存拷贝延迟

c10/cuda/CUDAStream.h:60-88

当前设备管理

c10/cuda/CUDAFunctions.cpp:107-141

多 GPU 时必须确保操作的数据和核函数在同一设备上。

同步操作的成本

隐式同步点

以下 PyTorch 操作会触发隐式同步：

c10/cuda/CUDAFunctions.h:78-108

这些操作会强制 CPU 等待 GPU 完成队列中所有任务：

操作 同步原因
tensor.item() 需要把 GPU 数值传回 CPU
torch.nonzero(tensor) 结果大小取决于计算结果
print(tensor) 需要将数据格式化输出

为什么昂贵？

在高性能代码中，要极力避免不必要的同步。

PyTorch 的错误处理哲学

边界检查

对于 Embedding 等操作，PyTorch 进行边界检查：

而不是让 GPU 执行一个”非法内存访问”，产生模糊错误。

为什么这样做？

选择 性能 调试体验
省去边界检查 稍好 遇到问题时很难定位
保留边界检查 略有损失 得到清晰的错误报告

PyTorch 选择错误报告优先，即使牺牲少量性能。

总结

理解 CUDA 异步执行的关键点：

概念 说明
异步执行 CPU 发起命令后立即返回，GPU 在后台执行
同步成本高 tensor.item()、print() 等操作强制等待
调试用 CUDA_LAUNCH_BLOCKING 强制同步，精确定位错误
Streams 保证顺序 同一 Stream 内按顺序执行
错误报告优先 PyTorch 宁可牺牲少量性能，也要清晰的错误信息

当你和 GPU 打交道时，记住：发出的命令不会立即完成。这个认知将帮助你更好地理解性能瓶颈、调试诡异错误。
