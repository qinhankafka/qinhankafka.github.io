PyTorch CPU 向量化：Vec256 与运行时动态分发

引言：为什么需要向量化？

在深度学习中，我们处理的不是单个数字，而是庞大的张量。如果 CPU 一次只能处理一个数字，效率会非常低下。

向量化（Vectorization）利用 SIMD（Single Instruction, Multiple Data）并行计算模式，让 CPU 用一条指令同时对多个数据进行操作。

PyTorch 采用手动向量化策略，通过 Vec256 等 C++ 抽象层编写向量化代码，并通过运行时动态分发机制在不同 CPU 上保证兼容性和性能。

DispatchStub：运行时动态分发

核心问题

先了解一下 CPU 向量指令集的演进：

指令集 寄存器宽度 每次操作 float 数 说明
SSE 128 bits 4 个 早期版本
AVX 256 bits 8 个 扩展到 256 位
AVX2 256 bits 8 个 增加更多整数指令
AVX-512 512 bits 16 个 宽度翻倍，但有功耗问题

一个 2015 年的 CPU 可能只支持到 AVX2，而 2020 年后的高端 CPU 才支持 AVX-512。

兼容性问题

如果 PyTorch 直接用 AVX2 编译，在不支持的 CPU 上会收到 SIGILL（非法指令）错误，程序直接崩溃。

编译机制

aten/src/ATen/cpu/vec/vec256/vec256.h

同一个源文件会被编译多次，每次使用不同的编译器标志（如 -mavx2），生成不同版本的函数，通过不同的 inline namespace 区分。

编译发生在哪里？

场景 多次编译发生在哪里
本地从源码编译 在你本地机器上，CMake 会配置多次编译，生成多个 .o 文件
官方 pip wheel 通常只在 Meta 的构建服务器上编译一次（通用 AVX2 版本）

可以只编译本地最高支持的版本吗？

答案是：默认不会，但可以控制。

PyTorch 的设计哲学是同时编译所有检测到的版本，运行时再选择。这样做的好处是：

  • 二进制可以在不同 CPU 上运行（兼容性）
  • 运行时动态选择最优版本（性能）

如果你想只编译本地最高版本，有两个思路：

思路一：使用 USE_NATIVE_ARCH

CMakeLists.txt:275

开启后，编译器会用本地 CPU 的最高指令集优化，但这不会阻止编译其他版本——PyTorch 仍然会编译 AVX2、AVX512 等版本，只是在当前机器上用 march=native 优化。

AVX-512 的权衡

你可能会问：既然 AVX-512 一次能处理 16 个 float，为什么 PyTorch 不全面拥抱它？

降频（Down-clocking）问题：在某些 Intel CPU 上，执行高功耗的 AVX-512 指令时，CPU 会自动降低核心时钟频率。如果程序在 AVX-512 和普通代码之间频繁切换，降频带来的性能损失可能抵消 AVX-512 的加速收益。

因此 PyTorch 社区对全面集成 AVX-512 持谨慎态度。

总结

PyTorch CPU 向量化系统：

组件 文件 作用
Vec256 aten/src/ATen/cpu/vec/vec256/ 向量化抽象，重载运算符
DispatchStub aten/src/ATen/native/DispatchStub.h 运行时内核分发
cpuinfo 运行时检测 识别 CPU 特性
多次编译 不同 -mavx* 标志 生成不同指令集版本

这套机制让 PyTorch 能在各种 CPU 上既保证兼容性，又最大化利用硬件的向量化能力。向量化不是”黑魔法”，而是一套精心设计的工程方案。
